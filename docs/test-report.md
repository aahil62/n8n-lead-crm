# Test Report — AI Lead Qualification, CRM, and Follow-Up System

**Status:** all 15 scenarios run live in a sandbox on 2026-10-17. Results: 14 passed, 1 partly passed (P1-E2E-013: the follow-up date passed, but the exactly-once reminder could not be proven because the sandbox Airtable base is missing the `reminder_sent_at` field). Testing found and fixed several real defects along the way. Each one is listed under "Defects found and fixed" below and in the row where it showed up.

**Run environment:** sandbox n8n 2.23.4 (Docker, localhost). The current repo workflow JSON was imported as separate `[TEST]` copies with sandbox IDs filled in. Accounts: Airtable test base, HubSpot test account, Asana test project, and a Groq-hosted `openai/gpt-oss-20b` model through an OpenAI-compatible endpoint. Fixture payloads were posted to the P1-01 webhook. Where a fixture's key had already been used by an earlier run, a suffix was added to `source_event_id` (shown in the row), because dedup would otherwise block it. Failure cases were forced on the test copies only:
- **401:** a deliberately invalid dummy HubSpot token.
- **429:** the deal-create call pointed at a local mock that always returns 429.
- **Notification failure:** an invalid Asana project ID.
- **AI timeout:** a 1 ms model timeout.

The sweeper and report test copies got a Manual Trigger so they could be run on demand. The sweeper test copy was also limited to the 013 lead, so it would not send reminders for every due lead in the sandbox base.

Executions 221-243 and the P1-E2E-004 history come from earlier runs on 2026-10-17. The July run of P1-E2E-001 (executions 75-77) has been pruned from the instance.

## Defects found and fixed during testing

| Area | Defect | Fix |
|---|---|---|
| P1-02 gate | Confidence of exactly 0.70 skipped review | Gate uses `<= 0.70`; prompt confidence rubric |
| P1-02 review path | No human alert on review | `Alert Human Reviewer` Asana task |
| P1-02 merge | Returning-lead facts never merged | Load all leads by email, parse stored signals, newest wins |
| P1-02 follow-up | No natural-language follow-up date | "Check back with me in N days/weeks" sets `follow_up_at` from `received_at` (Asia/Kolkata) |
| P1-03 HTTP options | `fullResponse`/`neverError` mis-nested, so ignored | Correct nesting; write calls retry 3 times |
| P1-03 contact failure | Company and deal still written after a failed contact create | `Contact Captured?` gate |
| P1-03 deals | Returning qualified lead created a second deal | `Search Open Deal` → reuse an open deal |
| P1-03 classification | 4xx validation errors marked transient/retryable; dead-letter attempts hard-coded to 3 | 4xx (except 401/403/429) marked permanent; real attempt count |
| P1-01 intake | Idempotency key placed in an Airtable formula without escaping quotes | Quotes and backslashes escaped (same for the email lookup in P1-02) |
| P1-04 sweeper | Invalid Airtable formula; never wrote `reminder_sent_at`; sent the reminder before recording it, so any failed write repeated the reminder | Valid formula; writes `reminder_sent_at` before creating the task |
| P1-05 report | Capped at 100 leads; no window; model id missing on the endpoint; AI failure stopped the report | All records, 7-day window, shared model, AI step continues on error |
| Fixtures | `.example` emails rejected by HubSpot; 010/012 never reached CRM; 002 expected an email draft P1 doesn't make | `@example.com`; "ready to start" added; 002 expectation aligned |
